# v102 — резервная копия и переезд на другой сервер

## 1. Зачем это вообще

Всё, что нажито игроками, лежит в папке `data` на диске сервера:

| Файл | Что внутри |
|---|---|
| `users.json` | аккаунты, пароли, монеты, друзья, сессии |
| `userskins.json` + `skinimg/` | скины игроков и их картинки |
| `maps.json` | карты из редактора |
| `logs.json` + `logimg/` | новости |
| `abuse.json` + `abuse/` | медиа общего шоу |
| `update.json` | таймер до обновления |

Новый сервер всегда стартует с пустой папкой `data`. Без переноса
переезд = потеря всего. Плюс на Railway диск стирается при **каждом**
деплое, если к сервису не подключён Volume — так что копия нужна не
только для переезда.

## 2. Что добавлено

Панель владельца («Ред» → раздел «Резервная копия»):

- **Скачать** — один JSON-файл со всем содержимым `data`. Кнопка рядом
  с «Восстановить»; файл называется `aibrofist-backup-ГГГГ-ММ-ДД.json`.
- **Восстановить** — выбрать файл бэкапа, подтвердить, подождать.
  Данные перечитываются **сразу, без перезапуска сервиса** — это важно:
  на Railway без Volume перезапуск стёр бы только что восстановленное.
- Текущие сессии (в т.ч. ваша) переживают восстановление — из аккаунта
  не выкидывает посередине.

Маршруты `GET /owner/backup` и `POST /owner/restore` отвечают чужому
«Not found» — о их существовании обычный игрок не узнает. Пути из
файла бэкапа проверяются дважды (строка + готовый абсолютный путь):
`../`, абсолютные пути и обратные слэши не проходят.

Лимиты: обычный бэкап берёт файлы до 25 МБ (суммарно до 120 МБ);
`GET /owner/backup?full=1` поднимает планку до 65 МБ на файл — нужно
только если в шоу лежат большие видео. Медиа шоу тяжелее лимита не
теряются навсегда — их можно загрузить заново в панели шоу.

## 3. Как переехать на другой сервер

1. **Старый сервер:** панель владельца → «Резервная копия» → «Скачать».
   Файл сохраните на диск.
2. **Новый сервер:** задеплойте этот же код (загрузите проект, как в
   первый раз). Если Railway — выберите регион **Frankfurt**, не тот,
   где стояло раньше: это единственный настоящий способ опустить пинг
   до 30–50 мс.
3. Зайдите на новом сервере под любым аккаунтом, откройте «Ред» →
   «Резервная копия» → «Восстановить» → выберите файл. Подтвердите.
4. Войдите под аккаунтом из бэкапа (его пароль — из бэкапа, тот, что
   был на старом сервере). Аккаунты, монеты, скины, карты и новости
   уже на месте.
5. **Сразу подключите Volume** (Railway → сервис → Volumes → путь
   `/app/data`): без него следующая перезаливка кода снова всё сотрёт,
   и восстановление придётся повторять после каждого деплоя.

## 4. Характеристики 2 vCPU / 1 GB — слабые?

Для этого сервера — нет. Node-процесс с socket.io держит сотни
одновременных игроков в скромные килобайты на игрока; v101 к тому же
убрал двойные соединения и рассылку «каждому каждый пакет». Пинг от
vCPU не зависит вообще — это расстояние до сервера. Слабое место
Railway-тарифа не характеристики, а **регион по умолчанию**.

## 5. Проверки

`test-backup.js` — 31 проверка: защита путей (`../`, абсолютные,
обратные слэши), права (чужой и без входа получают 404), сбор бэкапа
(данные, картинки в base64, пропуск тяжёлых, режим full), восстановление
(файлы на диске, перечитывание без перезапуска, живые сессии не теряются,
битый/чужой бэкап и опасные пути отбиваются). Все 12 тестовых файлов
зелёные. Дополнительно прогнан живой сервер: регистрация владельца →
скачивание бэкапа → восстановление в новое пустое хранилище.

Версии статики: `owner.js?v=102` (в восьми страницах). `backup.js` —
новый серверный файл, наружу не отдаётся: добавлен в поимённый список
приватных файлов server.js, как accounts.js и остальные модули.
