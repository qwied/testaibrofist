# v94 — платформа твёрдая: толкает, не телепортирует, не пропускает сквозь

## Что было не так в v92–v93

Я дважды промахивался с одного и того же места — с выбора **стороны**, в которую
выталкивать игрока.

- В v92–v93 быстрая платформа переставала быть твёрдой и продавливалась сквозь
  игрока. Это и есть «телепортирует сквозь объекты».
- В v88 сторона бралась по знаку `pl.vx`. Игрока, которого платформа догнала
  сзади, выбрасывало на её противоположный край — через весь блок разом.

## Как сделано теперь

Сторона выбирается так же, как посадка сверху в v92: **по тому, откуда игрок
пришёл**. Сравниваем, где был его бок и где была грань ДО этого шага.

```js
var leftWas  = Math.max(sp[0], sp[0] - pdx);   // грань: где была или где стала
var fromLeft = (xBefore + pl.w) <= leftWas + 2;
```

Вошёл слева — выходит слева, вошёл справа — справа. Никакого выброса на
противоположный край. Блок остаётся твёрдым: сквозь платформу больше не
проваливаешься.

Плюс потолок на скорость толчка — `PUSH_CAP = 16` px за кадр:

- обычная платформа за кадр проходит меньше и выносит игрока целиком, то есть
  толкает по-честному;
- слишком быстрая тащит игрока с этой скоростью и постепенно обгоняет —
  вместо рывка в 93 px за кадр.

Неподвижные блоки на эту ветку не заходят вообще: у них `pdx = 0`, и работает
прежнее выталкивание против движения.

## Замеры

| сценарий (ход 2000, скорость 8) | v88 | v92 | v94 |
|---|---|---|---|
| Рывок при толчке | 93 px/кадр | сквозь | **16 px/кадр** |
| Проваливается сквозь платформу | нет | да | **нет** |
| Стоять на едущей платформе | 0 % кадров | 100 % | **100 %, зазор 0 px** |
| Прыжок на статичную полку, 2640 сценариев | эталон | 0 расхождений | **0 расхождений** |

## Сила прыжка

Осталась как в v93: `JUMP_H = 168`, первые 7 кадров подъём не режется. Тап на
телефоне даёт 133 px, зажатая кнопка — 161 px (было 80 и 116). Ряды полок на
картах стоят в 83–104 px, так что до соседнего теперь долетаешь и тапом.

Версии статики подняты до `?v=94`.
